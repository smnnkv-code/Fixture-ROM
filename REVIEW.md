# REVIEW.md — код-ревью FIXTURE_ROM (фаза 1: анализ)

Дата: 2026-07-27. Ревью проведено ПОСЛЕ рефакторинга от 27.07 (см. `refactoring-report.md`) — таблица ниже содержит только проблемы, актуальные для текущего кода.

## Контекст проекта

**Назначение** (по README): сбор прошивок световых приборов с сайтов производителей (16+ брендов), нормализация имён файлов, раскладка на флешку FIXTURE_ROM, локальный веб-дашборд для управления.

**Структура** (~4450 строк Python, 6 модулей):

```
FixtureROM/
├── sync.py          (2159) — точка входа: скраперы, скачивание, копирование на USB, metadata.json
├── gui.py           (1451) — веб-дашборд на stdlib http.server (localhost)
├── diff_engine.py    (202) — сравнение снапшотов структуры, ведение blacklist/rules
├── rename.py         (208) — утилита переименования существующих файлов
├── rom_common.py     (338) — общая библиотека (clean_model_and_version, get_usb_root, sha256, ANSI)
├── snapshot.py        (93) — снапшот структуры с SHA-256
├── requirements.txt        — requests, beautifulsoup4
├── config.json / blacklist.json / rules.json / Downloads/ (данные) / docs/
```

**Стек**: Python 3, stdlib + `requests`; веб — голый `http.server`; БД нет — JSON-файлы; менеджер зависимостей — pip.
**Тесты, линтеры, CI**: отсутствуют.

**Статус прошлого ревью** (code-review-report-kimi3.md): исправлено и проверено в коде 10 из 20 находок, включая все 4 критичные: bind 127.0.0.1 (gui.py:1426), экранирование AppleScript `_as_escape` (sync.py:1537), атомарный `sync_file_to_usb` с try/OSError (sync.py:1426-1447), починка blacklist по `new_filename` (sync.py:1982 + diff_engine.py:102-111). Также: общий модуль `rom_common.py`, ретраи `download_file` (sync.py:1367-1420), валидация `/api/config/save` (gui.py:1269-1305), `sync_lock` (gui.py:104,1236), warning фильтра моделей (sync.py:1873), секция `modified` в diff-отчёте (diff_engine.py:64-79).

## Итоговый вывод

После рефакторинга 27.07 критичных проблем в коде не осталось — все четыре (открытый дашборд, AppleScript-инъекция, краш при извлечении флешки, сломанный blacklist) исправлены и проверены в коде. Оставшийся профиль рисков — надёжность при сбоях (тихие `except`, неатомарная запись JSON, отсутствие политеса в скраперах) и долг поддерживаемости (монолитный `main()`, ноль тестов). Отдельное внимание — #3: рефакторинг молча изменил поведение rename.py, это нужно задокументировать до того, как пользователь прогонит его по старой коллекции.
